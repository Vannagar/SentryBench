# Replay the graph to find turning points

**The idea, in plain language:** record everything a multi-agent run does (each message, tool call, read and channel creation) as a node in a graph, and draw an edge whenever a later action could have seen an earlier event. Then ask each edge one question: *if this earlier event had not happened, how much less likely would the later action be?* The events whose removal most changes what happens next are the inflection points. Cheap signals (a one-pass likelihood check on every edge, plus a per-agent activation probe watched by a change-point alarm) produce a short list. The top few are then confirmed by re-running the system from just before them with open-weight models. The result is a general monitoring and interpretability tool for any kind of later behaviour. The approach is new because no published system yet combines all three of these: a general event graph over LLM-agent runs, edge weights measured by intervening on the run, and any kind of behaviour shift, not only task failure. Existing graphs are structural only, and existing "decisive step" methods label one failure step without a graph. The first experiment uses an LLM naming game run with open-weight Llama agents, where a committed minority overturns an established convention ([Ashery et al.](https://arxiv.org/abs/2410.08948v1)). It is a tipping point with a known mechanism and a known onset time built into the setup.

## Inflection means "changes the outcome when removed", tested two ways

The literature already agrees on a definition. Who&When defines the decisive error as the earliest agent-step whose correction flips failure to success ([Who&When](https://arxiv.org/html/2505.00212)). Thought Anchors scores a sentence by how much the final-answer distribution shifts when that sentence is resampled ([Thought Anchors](https://arxiv.org/html/2506.19143)). Pivotal-token and forking-token work use the same logic at the token level ([Phi-4](https://arxiv.org/html/2412.08905v1); [Forking Paths](https://arxiv.org/html/2412.07961)). The open questions are how to make that test affordable on a graph, and what to call an inflection when nothing "fails".

The recommended answer is to measure at two levels, because the two levels answer different questions. A **teacher-forced score** keeps the later output fixed and measures the drop in its log-probability when one upstream event is removed. That takes one forward pass and gives the event's *direct* effect. AttriBoT makes exact leave-one-out **over 300x faster** with only a 10% mAP drop, and an 8B same-family proxy tracks a 70B model at r = 0.94 ([AttriBoT](https://arxiv.org/pdf/2411.15102)). A **rollout score** re-generates everything downstream and measures how far the outcome distribution moves. That captures the *total* effect through intermediate events, at much higher cost and variance ([CAR](https://arxiv.org/abs/2606.08275); [C3](https://arxiv.org/abs/2603.06859)). The gap between the two scores approximates the indirect effect that flows through intermediate events. No verified paper reports this direct/indirect split for LLM agent pipelines, so it is a contribution in its own right.

The cheaper shortcuts are worse in ways that matter here. LLM judges do not faithfully approximate ablation ([Agents that Matter](https://arxiv.org/abs/2605.27621)). Raw attention is model-dependent and unreliable on Phi-3 ([ContextCite](https://arxiv.org/html/2409.00729v2)). Judge-based step localisation on Who&When reaches only **14.2%** step accuracy ([Who&When](https://arxiv.org/abs/2505.00212)). The ground-truth labels are themselves defined by counterfactual correction, so only intervention-based scores measure the same thing as the labels.

| Tier | What it measures | Cost | Role |
|---|---|---|---|
| Teacher-forced leave-one-out Δlog p (AttriBoT-style) | Direct effect of event on a later action | ~1 forward pass per edge, cut further with KV cache and a small proxy model | Weight every edge |
| Probe score per agent turn + CUSUM/BOCPD | When an agent's internal state shifts toward the eventual action | Near-free once the probe is trained | Flag candidate onset times online |
| Rollout resampling from prefix (Thought Anchors-style, 10–20 samples) | Total effect on the final outcome | Tens of full continuations per candidate | Confirm the top-k only |
| Shapley / interaction scores on top-k | Credit split among redundant events | Many more calls | Only where leave-one-out scores near zero |

Forking Paths found 10–20 samples per position about as good as 30 ([Forking Paths](https://arxiv.org/html/2412.07961)). The screen-then-verify pattern is also what the strongest failure-attribution methods do: causal-inference attribution reaches up to **36.2%** step accuracy ([Ma et al.](https://arxiv.org/abs/2509.08682)), and EMFA claims further gains by screening on propagation and then verifying counterfactually ([EMFA](https://arxiv.org/abs/2610.11600)).

## Five strands of prior work supply the parts, but none supplies the whole

| Strand | Best work to build on | What it gives | What it lacks |
|---|---|---|---|
| Graph representation | DIG bipartite activation/event graph ([DIG](https://arxiv.org/html/2603.00309v2)); SentinelAgent typed message/tool edges ([SentinelAgent](https://arxiv.org/html/2505.24201)); PROV-AGENT lineage ([PROV-AGENT](https://arxiv.org/abs/2508.02866)) | Schemas that map to post/read/tool/channel events | Edges are structural, with no causal weights |
| Causal attribution | ContextCite, AttriBoT, AT2 ([AT2](https://arxiv.org/html/2504.13752)); CausalArmor leave-one-out at agent decision points ([CausalArmor](https://arxiv.org/abs/2602.07918)) | Validated interventional edge weights on open models | Single context or single decision point, not a multi-agent graph |
| Critical-step detection | Who&When, AgenTracer-8B (Qwen3-8B, 20.7% / 42.9% step accuracy) ([AgenTracer](https://arxiv.org/html/2509.03312)); Point of No Return, which localises deceptive commitment by resampling ([2605.17113](https://arxiv.org/abs/2605.17113)) | Counterfactual definition of "decisive"; a trained open tracer as a baseline | One earliest step per failure; labels come from closed-model traces |
| Change-point detection | One-sided CUSUM with an adaptive threshold ([AAF](https://arxiv.org/html/2512.18561)); CUSUM over hidden-state risk flags jailbreaks ~1.1 turns early ([SafeDream](https://arxiv.org/abs/2604.16824)); BOCPD ([Adams & MacKay](https://arxiv.org/abs/0710.3742)) | Detection-delay and false-alarm guarantees | AAF's agents are RL, not LLMs; no change-point detection on LLM multi-agent streams |
| Internal/probe signals | "The Agent Knew": probe AUROC 0.58 just after the trigger, 0.94 at the decision ([2610.17301](https://arxiv.org/html/2610.17301)); HELIOS per-agent probes reach 0.99–1.00 AUROC on steganographic collusion ([NARCBench](https://arxiv.org/abs/2604.01151)) | Cheap, early, white-box onset signal | No per-turn localisation in multi-agent settings |

The gaps line up neatly. Only AAF puts statistically inferred causal edges on an event graph, and only for RL agents, using Granger tests that the paper itself calls an approximation ([AAF](https://arxiv.org/html/2512.18561)). The one LLM dependency-graph attribution paper, GraphTracer, was **withdrawn for a methodology error** ([GraphTracer](https://arxiv.org/abs/2510.10581)). NARCBench probes agents only after the first prompt and at the end, and lists sequential detection as future work ([NARCBench HTML](https://arxiv.org/html/2604.01151)). Every dataset with step-level decisive labels was generated mainly by closed models: Who&When used GPT-4o and TRAIL used o3-mini and Claude ([Who&When HF](https://huggingface.co/datasets/Kevin355/Who_and_When); [TRAIL](https://huggingface.co/datasets/PatronusAI/TRAIL)). The novel contribution is therefore an open-weight event graph with interventional edge weights, defined for any behaviour shift (convention flips, deception, collusion), not only failure, that allows several causes per outcome, and that treats channel creation as a first-class node.

## A first experiment: a naming game where a minority tips the convention

In the Ashery et al. naming game, LLM agents converge on a shared convention without being told to. A committed minority above a critical size then overturns it. The effect holds across Llama-2-70b-Chat, Llama-3-70B-Instruct and Llama-3.1-70B-Instruct ([Ashery et al.](https://arxiv.org/abs/2410.08948v1)). This gives a known onset time built into the setup: the moment the minority enters. The minority size can also be varied, so runs just below the critical size serve as matched controls in which no flip should occur. Choices are short names, so outcomes can be scored without a judge. The exact critical sizes and any code release were not checked, so the plan is to re-run the game with open Llama models.

| Step | What to do | Output |
|---|---|---|
| 1. Build graphs | Log every pairwise interaction as an event. Draw an edge from each event to every later choice whose context contained it. Mark the minority's entry as the known onset. | One event graph per run |
| 2. Vary the knob | Run minority sizes below and above the tipping size, and vary the entry time | Flipping runs and non-flipping controls |
| 3. Edge weights | Teacher-forced leave-one-out Δlog p of each later choice, using Llama-3.1-8B as a proxy and re-scoring the top edges with 70B (an 8B proxy tracked 70B leave-one-out at r = 0.94 ([AttriBoT](https://arxiv.org/pdf/2411.15102))). Replace removed events with a placeholder. | A weighted graph |
| 4. Online signals | Probe each agent's hidden state for its upcoming choice (pre-CoT probes predict final answers at >0.9 AUC ([Cox et al.](https://arxiv.org/abs/2603.01437))). Run CUSUM/BOCPD on the probe stream. Add early-warning statistics (rolling variance and lag-1 autocorrelation of the adoption fraction ([Scheffer et al.](https://ideas.repec.org/a/nat/nature/v461y2009i7260d10.1038_nature08227.html))). | Candidate onset per run |
| 5. Gold check | For the top-5 candidate events per run, resample the event and re-run downstream 10–20 times. Measure how much the probability of a flip shifts. | Rollout importance |
| 6. Score | Measure: whether top-ranked events fall at or after the known onset; Spearman correlation of cheap scores against rollout importance; detection delay and false-alarm rate on below-threshold controls | Main results table |

Baselines: an open-weight LLM judge, AgenTracer-8B, raw attention and token-entropy CUSUM. The headline claim to test is that **leave-one-out graph weights plus probe-based change-point detection find the events that tip the population more often than judges, at a small fraction of full-replay cost**. The direct/indirect split shows whether the new convention spreads by direct contact with the minority or through agents it has already converted. NARCBench (Qwen3-32B-AWQ transcripts and exact prompts, MIT ([NARCBench repo](https://github.com/aaronrose227/narcbench))) is an optional second case: a coalition steering a committee vote.

## Six risks could make the scores misleading

| Risk | Why it bites | Mitigation |
|---|---|---|
| Removing an event creates an unnatural context | A dangling reference to a deleted message makes the context out-of-distribution | Use placeholder replacement and report the protocol; removal protocols "induce distinct games" ([Agents that Matter](https://arxiv.org/abs/2605.27621)) |
| Redundant causes | Two messages carry the same information, so each leave-one-out score is near zero | Run Shapley or ProxySPEX on the top-k ([ProxySPEX](https://arxiv.org/html/2505.17495v2)) |
| Rollout noise | Two 16-continuation references agree at only ~0.73 ([C3](https://arxiv.org/abs/2603.06859)) | Report confidence intervals; treat the replay score as noisy gold |
| Knowledge already in the weights | Context attribution is unfaithful when the model already knows the content ([2607.23804](https://arxiv.org/abs/2607.23804)) | Flag low-weight edges carrying common facts; rely on rollout there |
| Probes fire late | Probe AUROC is only 0.58 right after the trigger ([2610.17301](https://arxiv.org/html/2610.17301)) | Use probes for screening, never as the final verdict; a CUSUM alarm time is not the onset estimate |
| Narrow evidence base | One model family and one game; known onset marks when the cause arrives, not which event tips the population | Score against rollout importance, not onset alone; add NARCBench as a second, different setting |

## Conclusion

The inflection-point problem is not mainly a graph-building problem; structural event graphs are already standard. The hard part is putting *interventional* weights on the edges cheaply enough to use. The literature has quietly converged on screen-then-verify, and open-weight replay makes that loop possible on multi-agent runs for the first time. The payoff is general. The same weighted graph serves as a monitor, flagging a shift as it starts, and as an explanation, naming the past events that dictated where the system went. That applies to any behaviour, whether a convention flip, a failure or a harmful turn. Setups with a known onset time built in are what make the explanations testable rather than plausible-sounding.
